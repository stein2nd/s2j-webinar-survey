# S2J Webinar Survey - 永続化と受け渡し

## 設計意図 (ゴール)

1イベント1アンケートを保護メタに保存し、`ready` の場合だけ S2J Webinar が読めるようにします。

本プラグインは、Zoom を呼びません。

## 保存

| 項目 | 内容 |
| --- | --- |
| 単位 | 1イベントにつきアンケートは1つ |
| キー | `_s2j_webinar_survey` (保護メタ) |
| 中身 | メタ文書 (サービス形 + `status`) |
| 助言・不足コード | メタ文書に残さない。表示時はパネル文書への揮発の `evaluate` で再計算 |
| 下書き候補 | メタ文書に書かない |

### 用語 (本プラグイン内)

| 用語 | 意味 |
| --- | --- |
| パネル文書 | 編集中の作業コピー (未保存可) |
| メタ文書 | `_s2j_webinar_survey` に保存された正規化済み文書 (`status` 含む) |
| 下書き候補 | 下書き UI の一時データ (パネル文書にもメタ文書にも未確定)。文書の `status: draft` ではない |

サービス仕様の「文書」は形の話である。本プラグインでは上記で修飾する。

### 保存のトリガー

* 初版では、**GatherPress イベント編集画面からの明示の投稿「更新」** に限定する。パネル専用の「アンケートだけ保存」は持たない。
* **含める:** ブロックエディター／イベント編集からの投稿「更新」。
* **除外** (`evaluate` もメタ上書きもしない): autosave、リビジョン (`DOING_AUTOSAVE`、リビジョン保存を弾く)、Quick Edit、一括編集、WP-CLI、**本プラグイン独自のカスタム REST によるメタ保存** (初版)。
* **許可:** エディター経由のコア投稿更新 REST (メタの `show_in_rest` 搬送) + `save_post` でのサーバー正規化。
* 理由: Webinar が読む `ready` を、パネル外の不完全更新で汚さない。独自 REST / CLI 保存を足す場合は、別イニシアチブで条件を広げる。

### 保存パイプライン (役割分担)

正規化の正はサーバーである。クライアントが送る生メタは搬送用であり、正本にしない。

**パネル文書の載せ方 (初版):** 保護メタ `_s2j_webinar_survey` は `register_post_meta` で `type` = `object` (または object 相当)、`show_in_rest` = true、`auth_callback` は当該投稿の `edit_post` 相当とする。編集画面に載せ、保存時は `save_post` でサーバーが `evaluate` し、正規化結果で上書く。クライアント生値は搬送用。正本はサーバー書き戻し後のメタ文書である。カスタム REST だけでパネル文書を別経路保存する案は初版に入れない。

REST で受け付ける形は、サービス文書と同型のパネル文書 (`status` なし可) である。クライアントが送った `status` は信頼せず、保存時の `evaluate` 戻りで上書く。プロパティごとの JSON Schema (各設問フィールドの詳細) は実装でよい。意味・必須は Survey Service の `document_spec` / `data_contract_spec` を正本とする。

1. パネルは作業中の **パネル文書** を上記メタ (REST entity) に載せる (未正規化でよい)。
2. 明示の投稿保存で `save_post` (相当) がパネル入力相当を受け取り `evaluate` する。
3. 戻り (正規化文書 + `status`) でメタ文書を書く。**成功時は、常に上書く。失敗時はメタを書かない。** クライアント生値をそのまま正本にしない。
4. **明示の投稿保存が成功したら、パネル文書をメタ文書 (正規化結果) に必ず合わせる。** 失敗した場合はメタ文書を書かず、適切な失敗メッセージを出す (パネル文書は編集中のまま)。

**「成功」の意味:** `evaluate` が例外なく完了したこと。戻りが `draft` でも `ready` でもメタに書く (`status=draft` の保存は失敗ではない)。例外・権限失敗では書かない。

#### `max_questions` の読み出し (投稿保存・表示専用・下書き共通)

サイト option `s2j_webinar_survey_max_questions` を使う。Settings API の値が文字列でも **`(int)` してから** Service に渡す。文字列のまま渡さない。未設定・空・`(int)` 後に1未満または15超は、渡す値を **6** とする。設定画面の保存時は1〜15以外を受け付けない ([admin_ui_spec.md](./admin_ui_spec.md))。

#### 投稿保存時 (`evaluate` → メタ文書)

1. パネル文書を入力配列にそろえる。
2. 上記の読み出しで `max_questions` (`int`) を決める。
3. `evaluate( $document, $max_questions )`。
4. 戻り (正規化 + `status`) をメタ文書として書く (**成功時は、常に上書く。失敗時は書かない**。上記の「成功」定義に従う)。
5. 不足・助言をパネル用の適切なメッセージ文にする (i18n 経由。永続化しない。多重度は Service の戻りどおり。重複除去しない)。
6. パネル文書をメタ文書に同期する (上記ステップ4成功時)。

#### 表示専用 `evaluate` (メタ非書き戻し)

発火と入力は、下記のとおりである。**入力は常にいまのパネル文書**である。メタ文書はパネル初期化の読み出し元と「状態」バッジ用だけにする。

搬送は **UI → 本プラグイン PHP (REST 等) → Service** である。クライアントから Service を直接呼ばない。

初版の発火は下記2つと投稿保存時のみである。キー入力のたびには走らせない。編集中の不足・助言メッセージは直前の結果のままとする。ライブ再計算・タブ間通知は別イニシアチブとする。

| 発火 | 入力 |
| --- | --- |
| パネルを開いた際 / イベント編集の再読込 | メタ文書をパネルに載せた直後のパネル文書 (未編集ならメタ文書と同内容)。**このリクエスト処理時点** のサイト option (`int` 化後。未設定等は6) |
| 下書き採用直後 | 採用反映後のパネル文書。上限の読み出しは同上 |

サイト設定で上限を変えても、開いたままのイベント画面は自動更新しない。新しい上限は、**次回パネルを開いた／イベント編集を再読込した際** に反映する (かつての「サイト上限変更後の再表示」はこの開き直しに含める)。投稿保存時も、そのリクエスト処理時点の同じ読み出し規則を使う。

1. 上記のパネル文書と、読み出した `max_questions` (`int`) で `evaluate` する。
2. 不足・助言のメッセージだけ更新する。コード列の多重度は Service の戻りどおり (同じコードが複数回なら同じ msgid を複数回出す。重複除去しない)。
3. メタ文書は書き戻さない。メタの `status` は前回保存のままとし、次の明示の投稿保存で追随する。
4. パネルで「状態」と出す場合は、メタ文書の保存済み `status` (`draft` / `ready` のコード) のみとする。**仮の `status` フィールドは持たない。** 不足の有無は `deficiencies` からメッセージにする。メタの「状態」と同じ見た目の第二バッジは出さない。
5. メタ未作成 (初回未保存) の場合は「保存済み: draft / ready」を出さない (出すなら製品文案で「未保存」)。日本語で状態を「下書き」と呼ばない (下書きは下書き候補／DraftKind)。S2J Webinar はメタ文書の `ready` だけを読むため、未保存は添付対象なしと整合する。
6. 二層表示 (未保存の変更と保存済み状態) は、**直前の `deficiencies` / `advice` (メッセージ) とメタ文書の `status` の対比**で足りる。初版 REST に `status` を足さない。

下書き候補の採用はパネル文書に足すだけである。メタ文書への書き込みは、次の明示の投稿保存で行う。

### 表示専用 `evaluate` の REST 最小契約

形は下記を正本とする。パスを変える場合は別イニシアチブと改訂履歴で行う。

| 項目 | 契約 |
| --- | --- |
| パス | `POST /wp-json/s2j-webinar-survey/v1/evaluate` |
| 権限 | `current_user_can( 'edit_post', $event_id )` 相当 (対象イベントを編集できること) |
| 入力 | **`event_id` (投稿 ID) 必須**、パネル文書。`max_questions` はサーバーがサイト option から読む (`int` 化。クライアント任意上書きは初版しない) |
| 出力 | **初版はコード列のみ:** `deficiencies`、`advice`。`status` / `document` は足さない。正規化プレビューは後続。**メタは書かない** |
| 失敗 | 権限不足・不正入力は適切な HTTP ステータスとメッセージ。Service の `InvalidArgumentException` はログし、ユーザー向けは簡潔な失敗メッセージ |

下書きも同じく UI → 本プラグイン PHP → Service とする。初版は1リクエストにまとめ、REST 最小契約は [draft_ui_spec.md](./draft_ui_spec.md) を正本とする。

## 無効化・アンインストール

イベントをゴミ箱に移しても、完全削除しても、本プラグインは Zoom を変更しません。

| 操作 | メタ `_s2j_webinar_survey` | サイト設定 | Zoom 上のアンケート |
| --- | --- | --- | --- |
| 無効化 | 残す | 残す | 変更しない |
| アンインストール | 消す | 消す | 変更しない |

## S2J Webinar との受け渡し

* `ready` の文書は上記メタ (`_s2j_webinar_survey`) にある。
* S2J Webinar は、通常の「同期」で **投稿メタを直接読み** `attach_survey` する (create の必須条件にしない。後から `ready` になっても同じ入口)。**本プラグイン向けの公開 PHP / REST bridge は初版に置かない。** 正本は相手の [survey_handoff_spec.md](https://github.com/stein2nd/s2j-webinar/blob/main/docs/survey_handoff_spec.md)。
* `draft` は読まない。
* S2J Webinar が無効でも、本プラグインの編集と保存はできる。
* 添付 HTTP と Zoom 設問型への写像は S2J Webinar / webinar-service が持つ。
* 本プラグインは Zoom の型名を持たない・送らない。
* アンケートの見出し・説明など Zoom 添付時のデフォルト値は、相手側 (S2J Webinar / webinar-service) の仕様である。本プラグインは保持・送信しない。
* 内部名 (`internal_name`) は文書の一部としてメタに保存する。Zoom 一覧向けであり、回答者文面には使わない (添付での扱いは相手側)。

下記は、初版で相手側が扱う答え方の目安です (写像の正本は、webinar-service)。

| 文書 `answer_kind` | Zoom `type` (相手側) |
| --- | --- |
| `single` | `single` |
| `multiple` | `multiple` |
| `short` | `short_answer` |
| `long` | `long_answer` |
| `rating` | `rating_scale` |
